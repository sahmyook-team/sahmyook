# 결재 검토 규칙 (GSC 나에안식 / 주거유지지원사업)

## 대상
- 구글 드라이브 `work` 폴더(ID `1vc-VbM-IhOdOjw3j3brFqMZjDL1N4iI9`) 안의 `결재` 폴더(ID `1niB7h-8MpRySPdhMHMGa5ZU79G64remY`).
- 결재 1건 = zip 1개. zip 안에 전자결재 본문(.mht)과 첨부(hwp, pdf, png, jpg)가 있다.
- 이미 검토한 파일은 프로젝트 문서 `claude/결재검토/검토이력.md`에 파일 ID로 기록돼 있다. 기록에 없는 zip만 검토한다.

## 처리 순서
1. `search_files`로 `parentId = '1niB7h-8MpRySPdhMHMGa5ZU79G64remY'` 목록을 가져와 검토이력에 없는 zip만 고른다.
2. `download_file_content`로 받으면 로컬 파일 경로가 돌아온다. 결재마다 새 빈 폴더에 `unzip -q -O cp949`로 푼다. (파일명이 `#Uc6d4` 형태로 나오면 `chr(int(hex,16))`로 복원해서 읽는다.)
3. 본문(.mht): 아래 `mht.py`로 텍스트 추출(UTF-8). 초과근무 양식의 `<DATA>` XML은 무시해도 된다.
4. 첨부:
   - PDF: `pdftotext -layout`; 글자가 안 나오면 `pdftoppm -r 70 -png`로 렌더링해서 본다(여러 쪽은 가로로 이어 붙여 한 장으로).
   - HWP: `pip install pyhwp --break-system-packages` 후 `hwp5txt`; 표는 `hwp5proc xml`에서 `<Text>` 추출, 그림은 `hwp5proc unpack` 후 `BinData/*.bmp`.
   - 이미지: 아래 "개인정보 처리" 규칙을 먼저 적용.
5. 건별로 아래 점검 항목을 대조하고 결과를 작성한다.
6. 결과를 프로젝트 문서 `claude/결재검토/결과/YYYY-MM-DD.md`에 추가(같은 날 문서가 있으면 읽어서 뒤에 붙여 전체를 다시 저장)하고, 검토한 파일 ID를 검토이력에 추가한다.

## 개인정보 처리 (필수)
- 파일명에 통장, 신분증, 주민, 면허, 등록증, 여권이 들어간 이미지와, 지출 결재에 첨부된 사진 형태 이미지는 **열기 전에** `mask_pii.py`를 돌린다:
  `python3 -I mask_pii.py <이미지> <출력폴더> <본문에 적힌 그 사람(거래처) 계좌번호>`
- 결과 JSON의 `safe_to_view`가 true일 때만 `masked_*.png`를 연다. false면 이미지를 열지 않고 "통장사본 자동 대조 불가 – 직접 확인 필요"로 보고한다. `id_card_suspected`가 true면 "신분증 동봉 의심 – 가린 사본으로 교체 요청"도 함께 적는다.
- 견적서·영수증·고지서처럼 사업자 서류는 그대로 봐도 된다.
- 결과 문서와 답변에 주민등록번호, 면허번호, 개인 주소, 생년월일은 절대 옮겨 적지 않는다. 입주민 이름은 필요할 때만 쓴다.

## 점검 항목
**공통**
- 본문 안 금액 일치: 소요예산 = 산출내역 합계 = 첨부(견적·영수증·고지서·계획안 예산표) 금액. 한글 금액 표기도 확인.
- 인원·수량 일치: 본문 인원, 내역 합(예: 1+2+6), 회의록 참석자·서명 수, 단가×인원.
- 날짜 순서: 계획(실시) 결재 시행일 ≤ 견적일 ≤ 결제·시행일 ≤ 결과보고. 결제가 계획 결재나 서비스 제공보다 먼저면 지적.
- 재원·결제수단 일치: 세출원(보조금/자부담)과 지출방법(보탬e카드, 지방보조금카드, 법인카드, 계좌이체)이 맞는지. 영수증 카드 끝자리 확인.
- 예산과목(관·항·목·세목)이 지출 성격에 맞는지.
- 제목·본문·첨부의 사업명, 일시, 장소 표기가 같은지.
- 오탈자, 항목 번호 누락(가·나·다…).

**지출 (견적·거래처)**
- 견적서: 받는 곳이 우리 기관인지, 공급자란 기재가 정상인지, 제목과 품목이 맞는지, 견적일, 유효기간.
- 비교견적: 2곳 이상, 최저가 선정 여부, 비교견적서 자체의 형식 이상.
- 사업자번호: 견적서와 매출전표·세금계산서의 사업자번호, 상호, 대표자, 주소가 같은지. 가운데 두 자리로 유형 판단(81·86·87 법인, 01~79 개인과세, 90~99 면세 개인)하고 과세/면세 표기와 맞는지.
- 계좌이체: 계좌번호와 예금주가 거래처(또는 수령인) 명의인지, 통장사본이 첨부됐는지. 휴대폰번호형 계좌는 예금주 확인 요청.
- 공과금·통신비: 고지서 금액, 납부계좌, 사용기간, 납기일, 사용 장소(호수) 확인.
- 구입 품의: 품목별 가격·수량·구입처가 있는지.

**초과근무**
- 신청일과 근무일 비교: 사후 신청이면 며칠 늦었는지. "사전" 신청인데 결재 완료가 근무일 이후면 지적.
- 정규 근무시간 안의 시간(예: 17~18시)이 들어 있지 않은지, 아침 근무 포함 여부.
- 사유가 구체적인지, 평소 업무인지.
- 같은 제목 문서가 여러 개면 주차 표기 권고.

**휴가**
- 기간·구분·일수 계산, 잔여일수(신청 반영 전/후) 확인.

**수당·급여성 지급**
- 근거서류 장수 × 단가 = 금액, 서류 날짜가 대상 기간 안인지, 계좌·예금주가 통장사본과 일치하는지(개인정보 규칙 적용).

## 결과 형식 (한국어, 간결하게)
```
## YYYY-MM-DD 결재 검토 (N건)
### 결재 전 확인 필요
**번호. 제목 (기안자, 금액)**
- 문제 한 줄 + 근거(문서 A의 값 vs 문서 B의 값)
### 특이사항 없음
- 번호. 제목: 확인한 내용 한 줄
### 개인정보 주의
- 해당 건과 조치(가린 사본 요청 등)
```
- 가장 급한 것 한두 개를 맨 끝 한 줄로 요약.
